# Prompt 公共核心层 · 功能规格

> 适用模块：Prompt Bank、Prompt Mixer 及后续 Prompt 管理节点  
> 最后更新：2026-09-02

## 1. 功能定位

公共核心层负责数据和状态的可靠性，不负责 Bank 或 Mix 的具体业务界面。

```text
节点业务层
├─ Prompt Bank：多词条选择、排序、提示词权重
└─ Prompt Mixer：一级/二级 Tag 单选词组与节点折叠状态
            ↓
公共核心层
├─ 数据仓库
├─ Schema 与迁移
├─ 节点状态与快照
├─ Prompt 解析与拼接
├─ API 响应
└─ 弹窗事务
```

## 2. 共有能力

| 能力 | 责任 | 不负责 |
|------|------|--------|
| 数据仓库 | 列出、读取、创建、保存、导入、导出数据文件 | 决定 Bank 或 Mix 的业务字段 |
| Schema | 校验版本、名称、顺序和内容格式 | UI 排版 |
| 迁移 | 读取旧 YAML 并转换为当前格式 | 自动删除旧文件 |
| 状态读取 | 从节点 properties 读取选择状态 | 强制修改 widget 顺序 |
| 快照兜底 | YAML 无法匹配时保留旧工作流输出 | 静默隐藏失效状态 |
| Prompt 引擎 | 随机语法、提示词权重格式和分隔符拼接 | 决定选择哪些业务项 |
| API 契约 | 统一成功、失败、冲突及校验错误 | 在前端拼接服务器错误字符串 |
| 编辑事务 | 打开时创建草稿，保存时一次提交，取消时完整回滚 | 每次点击立即写文件 |

## 3. 推荐内部边界

### 3.1 适合放入薄基类

- 定位当前工作流节点。
- 读取指定 properties 字段。
- 解析状态并提供默认值。
- 返回统一的执行错误上下文。

### 3.2 适合独立服务而非继承

- 文件路径和原子保存。
- YAML Schema 校验。
- 数据迁移。
- Prompt 随机解析。
- 导入、导出和冲突检查。

这样可以避免产生同时了解文件、节点、Prompt 和 UI 的“万能基类”。

## 4. 数据关系

- Bank 与 Mixer 使用同一套存储、迁移和事务规则。
- Bank 文件保存原子词条库。
- Mixer 文件保存一级 Tag、二级 Tag 和中英文词条。
- 两类文件物理分开，避免语义混杂。
- Bank 与 Mixer 选择词条后都把中英文快照复制到 workflow，不建立词条 ID 引用。

## 5. 开发顺序

1. 定义公共 Schema 与用户数据目录。
2. 实现读取、校验、原子保存和迁移。
3. 实现节点状态读取及快照兜底。
4. 将现有随机语法接入公共 Prompt 引擎。
5. 为公共层补充无 UI 测试。
6. 接入 Prompt Bank 业务层。
7. 接入 Prompt Mixer 业务层。
8. 最后实现并验收两个弹窗 UI。

## 6. 验收底线

- UI 未打开时，节点执行仍能稳定工作。
- 插件升级不覆盖用户数据。
- 保存失败不损坏原文件。
- 取消操作不产生任何持久化修改。
- 旧工作流引用失效时仍有可预测输出。
- Bank 与 Mix 不复制各自的文件读写和 properties 解析代码。
