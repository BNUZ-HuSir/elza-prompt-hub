## 3. 必须重做、不能直接搬运的实现

### 3.1 节点与 widget

- 遗失版会把按钮 `pop()` 后 `unshift()` 到 widget 首位，会破坏工作流按索引序列化的稳定性。
- Mixer 会清空 `widgets` 后重新添加动态 widget。
- Mixer 和 Join String Multi 含有删旧节点、建新节点、尝试恢复连线的流程。
- Mixer 会强行包装 ComfyUI widget DOM，并调用 `setSize(computeSize())` 修改用户布局。

新版本继续遵守：不重建节点、不删除或重排 widget、不强改 ComfyUI 内部 DOM。复杂配置全部进入弹窗，节点本体只保留固定数量的原生输入和摘要。

### 3.2 文件存储

- 遗失版仍把用户数据放在插件目录，插件更新存在覆盖风险。
- 保存直接写目标 YAML，不是原子保存；中途失败可能损坏文件。
- 保存 API 接收前端传入的 `filename` 后直接拼接路径，缺少文件名白名单和路径边界验证。
- 同名一级分类合并后，只用一级分类名记录来源文件；跨文件同名分类会丢失准确来源。

新版本改为用户数据目录、稳定文件 ID、显式来源信息、Schema 校验和原子替换。

### 3.3 多词库文件管理

遗失版的文件管理弹窗维护了前端 `_pendingFiles`，但重新加载时仍调用“加载全部 YAML”的接口，没有把选中的文件列表传给后端，因此“移除文件”不能真正控制加载范围。

新版本不沿用该逻辑。文件选择器必须明确区分：

- 当前打开的词库文件。
- 已发现但未打开的文件。
- 合并视图需要显式开启，并保留每条数据的准确来源。

### 3.4 保存和取消

- Bank 的分类和词条 CRUD 会立即调用保存；用户点击取消只能取消节点选择，不能回滚词库修改。
- Mixer 的部分编辑也会直接保存。
- 保存失败主要依赖 `alert()`，状态反馈和恢复路径不足。

新版本采用双事务：

- “应用到节点”只更新当前节点状态。
- “保存词库/保存配方”只在管理模式提交数据草稿。
- 关闭时分别判断节点草稿和数据草稿，不混为一谈。

### 3.5 安全与可维护性

- 多处把分类名、词条内容和文件名拼入 `innerHTML`，存在 DOM 注入风险。
- `document.addEventListener("click", ...)` 没有对应移除，重复打开弹窗可能积累监听器。
- Python 多处捕获宽泛异常并向客户端返回原始错误字符串。
- 随机解析器只支持旧语法子集，不支持当前已确认的带权随机。

新版本统一使用安全 DOM 文本赋值、可释放监听器、结构化错误和当前 `prompt_syntax.py`。

## 4. 暂不合并

| 功能 | 原因 |
|------|------|
| Join String Multi | 与 Bank/Mix 核心层没有直接依赖，应单独立项 |
| 节点面板展示所有 Mixer 分组 | 分组多时节点会异常庞大，并需要危险的动态 widget 操作 |
| 通过数字 index 盲选候选项 | 用户看不到 index 对应文本，易错；改为弹窗内明确选择 |
| 即时写入 YAML | 无法可靠取消和回滚 |
| 旧 Prompt Switch 代码 | 当前 alpha.3 的 socket、连接优先、迁移和随机语法更完整 |

## 5. 合并后的目标结构

```text
prompt_core/
├─ storage        用户目录、文件发现、原子保存、冲突检测
├─ schema         Bank/Mix Schema、稳定 ID、校验、版本迁移
├─ workflow_state properties 读取、快照、失效引用兜底
├─ prompt_engine  当前随机语法、权重格式、片段拼接
└─ api            统一响应、错误码和保存事务

Prompt Bank
├─ 选择模式       搜索、来源定位、多选、排序、注意力权重
└─ 管理模式       文件、分类、词条、导入导出

Prompt Mix
├─ 配置模式       分组开关、固定/随机、seed、预览
└─ 管理模式       配方、分组和候选项 CRUD
```
